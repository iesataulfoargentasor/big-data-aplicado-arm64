02 / PREPARAR

Prepara el MacBook Air M4.

Instala Docker Desktop para Apple Silicon

Descarga la variante para Apple Silicon desde Docker, abre la aplicación y espera a que el motor esté listo. No necesitas instalar Java, Python, Spark ni Hadoop en macOS.

Asigna recursos y deja margen a macOS

Como punto de partida: 12 GB de RAM y 6 CPU en Settings → Resources. Reserva unos 25 GB libres para imágenes, caché y prácticas pequeñas. Son orientaciones, no una garantía para cualquier volumen de datos.

Descarga el proyecto en una carpeta local

Usa una carpeta fuera de iCloud Drive. Con Git instalado:

Terminal · carpeta del proyecto
mkdir -p ~/Proyectos
cd ~/Proyectos
git clone https://github.com/iesataulfoargentasor/big-data-aplicado-arm64.git
cd big-data-aplicado-arm64

Si prefieres el ZIP, descomprímelo y abre Terminal en la carpeta que contiene compose.yaml. Su nombre normalmente termina en -main; utiliza el nombre real. Git puede solicitar las herramientas de línea de comandos de Apple.

Comprueba Docker y detén el otro stack

Terminal · carpeta del proyecto
docker version
docker compose version

Debe aparecer Client y Server. Utiliza Compose 2.20 o posterior. Detén el otro laboratorio desde Docker Desktop: los stacks comparten algunos puertos. No hace falta borrarlo.

Todos los servicios de esta variante son ARM64. No necesitas activar Rosetta para ejecutarlos.
03 / DESPLEGAR

Arranca el escenario de la práctica.

Ejecuta los comandos desde la carpeta del proyecto. La primera construcción puede tardar varios minutos. El asistente comprueba que las imágenes del escenario sean ARM64.

A. Lago: Hadoop, Hive, MinIO y Trino

Terminal · carpeta del proyecto
bash preparar.sh lake
bash iniciar.sh lake
bash comprobar.sh lake

La prueba crea tablas de demostración y verifica HDFS, Hive y las consultas de Trino. Para probar también MapReduce sobre YARN:

Terminal · carpeta del proyecto
bash scripts/comprobar-yarn.sh

Para añadir el cliente Hadoop con Jupyter en localhost:8889:

Terminal · carpeta del proyecto
bash preparar.sh hadoop
docker compose --profile lake --profile hadoop up -d --no-build --pull never --wait --wait-timeout 900

B. ELT y Airflow

Detén el escenario anterior, prepara este y comprueba primero el flujo manual, después el DAG:

Terminal · carpeta del proyecto
bash parar.sh
bash preparar.sh elt
bash iniciar.sh elt
bash comprobar.sh elt
bash scripts/comprobar-airflow.sh
Cierra las conexiones DuckDB de Jupyter antes de ejecutar las pruebas. No lances el flujo manual y el DAG al mismo tiempo: comparten el archivo workspace/data/retail.duckdb.

C. Kafka

Kafka tiene su propio archivo Compose y su propio comando de parada:

Terminal · carpeta del proyecto
bash parar.sh
bash preparar.sh kafka
docker compose -f docker-compose.kafka.yml up -d --wait --wait-timeout 600
bash scripts/comprobar-kafka.sh

El comprobador crea un topic, produce y consume un mensaje y exige tres réplicas sincronizadas. Conserva el topic para explorarlo en la consola.

Los inicializadores que muestran Exited (0) han terminado correctamente. No son servicios que deban permanecer encendidos.

05 / TRABAJAR

Practica sin perder tus datos.

En el lago, HDFS guarda los archivos; Hive Metastore mantiene el catálogo en MySQL. Hive usa Tez local dentro de HiveServer2. YARN se prueba por separado con MapReduce. En ELT, Airflow coordina la extracción con dlt y las transformaciones de dbt.

Los volúmenes guardan HDFS, MySQL, PostgreSQL, MinIO y Kafka. Las carpetas workspace/ y notebooks/ guardan tu trabajo en el Mac.

Parar Lago o ELT

Terminal · carpeta del proyecto
bash parar.sh

Parar Kafka

Terminal · carpeta del proyecto
docker compose -f docker-compose.kafka.yml stop

Para cambiar de Kafka a Lago o ELT, detén Kafka antes y sigue el bloque de despliegue del escenario elegido. Para reanudar sin descargar imágenes:

Terminal · carpeta del proyecto
bash iniciar.sh lake
No uses down -v para una parada normal: elimina los volúmenes. Esta variante arranca con volúmenes propios y no migra automáticamente los datos de los repositorios antiguos.

En Docker Desktop verás bigdata-arm64-m4 y kafka-arm64-m4. Se conservan los nombres internos de la versión probada. Si ya usabas el ZIP validado con esos nombres, no ejecutes una segunda copia al mismo tiempo.

06 / EVIDENCIA

Los tres recorridos están probados.

  • Hadoop / Hive: Java y libhadoop ARM64; consultas sobre HDFS y MinIO; MapReduce en YARN.
  • ELT: seis modelos y once pruebas dbt; seis tablas y totales contrastados con MySQL.
  • Airflow: DAG real con tres tareas correctas; historial y datos conservados tras reiniciar.
  • Kafka: tres réplicas; producción y consumo con el líder detenido; mensajes conservados al recrear contenedores.
  • 14 imágenes distintas ARM64: escenarios comprobados por separado en el Mac.

Validación del 28 de octubre de 2026, con datos pequeños. No implica que todos los servicios deban arrancarse juntos ni garantiza rendimiento con cualquier carga.

07 / AYUDA

Diagnóstico sin borrar datos.

Docker no responde

Abre Docker Desktop y espera a que termine de arrancar. Ejecuta docker version: debe mostrar la sección Server.

Un puerto ya está ocupado

Detén el stack de la otra asignatura. En Spark puedes cambiar los puertos publicados en .env; en Big Data, en compose.yaml. Mantén los puertos internos y los nombres de servicio.

No puedo guardar archivos

Usa una carpeta local, compartida con Docker y escribible por tu usuario. Ejecuta preparar.sh sin sudo. Si copiaste .env de otro Mac, revisa sus UID/GID y vuelve a preparar la imagen.

El equipo se queda sin memoria

Ejecuta un escenario a la vez y reduce el tamaño del ejercicio. En Spark puedes elegir el modo ligero. Los límites de los contenedores no son memoria reservada ni garantizan que cualquier trabajo quepa.

Aparecen avisos o contenedores detenidos

Los avisos de Java, SLF4J o módulos opcionales de Hadoop no equivalen a AMD64. En Big Data, hdfs-init, minio-init, retail-init y airflow-init terminan normalmente con Exited (0). Una salida distinta de 0 o un estado unhealthy requiere consultar los registros.

Quiero preparar una clase sin Internet

Construye las imágenes y completa las pruebas con conexión. Los asistentes de inicio usan las imágenes locales. Los ejercicios que descarguen paquetes, datos o extensiones —como httpfs de DuckDB— requieren preparación previa.

Terminal · carpeta del proyecto
docker compose --profile "*" ps -a
docker compose logs --tail 100

En Kafka, añade -f docker-compose.kafka.yml a los comandos de diagnóstico. Los avisos de SLF4J o módulos Hadoop opcionales no significan que estés emulando Intel.
